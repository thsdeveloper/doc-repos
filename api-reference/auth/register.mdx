Use this endpoint to create a new Events Manager account. Depending on your deployment's email-confirmation setting, registration either completes immediately (returning a session) or enters a two-step flow where the user must verify their email address with a 6-digit OTP before their session is activated.

## POST /api/auth/register

### Request Body

<ParamField body="email" type="string" required>
  The user's email address. Must be a valid email format. Used as the login identifier.
</ParamField>

<ParamField body="password" type="string" required>
  The account password. Minimum 8 characters.
</ParamField>

<ParamField body="first_name" type="string" required>
  The user's first name. Must be at least 1 non-whitespace character. Also accepted as `firstName` for backwards compatibility.
</ParamField>

<ParamField body="last_name" type="string" required>
  The user's last name. Must be at least 1 non-whitespace character. Also accepted as `lastName` for backwards compatibility.
</ParamField>

### Response — 201 Created

When email confirmation is **not** required, the API sets session cookies and returns the full user object:

<ResponseField name="success" type="boolean">
  Always `true` on success.
</ResponseField>

<ResponseField name="confirmationRequired" type="boolean">
  `false` — registration is complete.
</ResponseField>

<ResponseField name="user" type="object">
  The newly created user profile including `id`, `email`, `first_name`, `last_name`, and `role`.
</ResponseField>

<ResponseField name="redirect" type="string">
  Suggested client-side redirect path — `/perfil` for new users.
</ResponseField>

When email confirmation **is** required:

<ResponseField name="success" type="boolean">
  Always `true`.
</ResponseField>

<ResponseField name="confirmationRequired" type="boolean">
  `true` — proceed to the confirm step.
</ResponseField>

<ResponseField name="email" type="string">
  The email address to which the OTP was sent.
</ResponseField>

<ResponseField name="message" type="string">
  A user-facing message confirming the email was sent.
</ResponseField>

## Email Confirmation Flow

When `confirmationRequired` is `true`, the user receives a 6-digit OTP at the registered email address. Submit it to `/api/auth/register/confirm` to activate the session.

### POST /api/auth/register/confirm

<ParamField body="email" type="string" required>
  The email address used during registration.
</ParamField>

<ParamField body="token" type="string" required>
  The 6-digit numeric OTP received by email. Must match the pattern `^\d{6}$`.
</ParamField>

On success, the API sets `access_token` and `refresh_token` cookies and returns the same session payload as `POST /api/auth/login` — `success`, `user`, `isOrganizer`, `isSuperAdmin`, and `redirect`.

### POST /api/auth/register/resend

If the OTP email was not received, request a new code. Pass only the registered email address:

<ParamField body="email" type="string" required>
  The email address awaiting confirmation.
</ParamField>

Returns `{ "success": true, "message": "..." }`.

## Rate Limits

| Endpoint | Limit |
|---|---|
| `POST /api/auth/register` | 20 req / hr per IP · 5 req / 10 min per email |
| `POST /api/auth/register/confirm` | 30 req / 10 min per IP · 10 req / 10 min per email |
| `POST /api/auth/register/resend` | 10 req / 10 min per IP · 3 req / 10 min per email |

<Warning>
  Exceeding any rate limit returns `429 Too Many Requests` with error code `RATE_LIMITED` and a `Retry-After: 60` header. Build appropriate retry logic before going to production.
</Warning>

## Examples

<CodeGroup>
```bash title="Register a new account"
curl -X POST https://<host>/api/auth/register \
  -H "Content-Type: application/json" \
  -d '{
    "email": "ada@example.com",
    "password": "s3cr3tPass",
    "first_name": "Ada",
    "last_name": "Lovelace"
  }'
```

```json title="Response — confirmation required"
{
  "success": true,
  "confirmationRequired": true,
  "email": "ada@example.com",
  "message": "Enviamos um código de confirmação para o seu e-mail."
}
```
</CodeGroup>

<CodeGroup>
```bash title="Confirm email with OTP"
curl -X POST https://<host>/api/auth/register/confirm \
  -H "Content-Type: application/json" \
  -d '{
    "email": "ada@example.com",
    "token": "847291"
  }'
```

```json title="Response — session created"
{
  "success": true,
  "user": {
    "id": "uuid-...",
    "email": "ada@example.com",
    "first_name": "Ada",
    "last_name": "Lovelace",
    "role": "user"
  },
  "isOrganizer": false,
  "isSuperAdmin": false,
  "redirect": "/perfil"
}
```
</CodeGroup>

<CodeGroup>
```bash title="Resend confirmation OTP"
curl -X POST https://<host>/api/auth/register/resend \
  -H "Content-Type: application/json" \
  -d '{"email": "ada@example.com"}'
```

```json title="Response"
{
  "success": true,
  "message": "Enviamos um novo código de confirmação para o seu e-mail."
}
```
</CodeGroup>
