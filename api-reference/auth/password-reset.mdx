title: "Password Reset via Email — Events Manager API Guide"

---

The Events Manager API provides a two-step, email-based password reset flow. First you request a reset link for a given email address; the user then clicks that link, which contains a short-lived `access_token`, and you submit the new password using that token. If the user is already logged in, they can change their password directly without going through the email flow.

## Step 1 — Request a Password Reset Link

Submit the user's email address to receive a reset link by email. The endpoint always returns a success response regardless of whether the email exists — this prevents email enumeration attacks.

### POST /api/auth/password/request

`POST /api/auth/forgot-password` is an alias for this endpoint and behaves identically.

<ParamField body="email" type="string" required>
  The email address associated with the account. Must be a valid email format.
</ParamField>

#### Response — 200 OK

```json title="Success (email found or not)"
{
  "success": true,
  "message": "Se o e-mail estiver cadastrado, as instruções serão enviadas."
}
```

The user receives an email containing a reset link that points to your configured `WEB_URL/redefinir-senha` with the `access_token` as a query parameter.

## Step 2 — Apply the New Password

Once the user clicks the reset link and your frontend extracts the `access_token` from the URL, submit it along with the new password.

### POST /api/auth/password/reset

<ParamField body="access_token" type="string" required>
  The token extracted from the password reset link sent to the user's email. This is a one-time-use token.
</ParamField>

<ParamField body="password" type="string" required>
  The new password. Minimum 8 characters.
</ParamField>

#### Response — 200 OK

```json title="Password reset successful"
{
  "success": true
}
```

After a successful reset, the user can log in with their new password using `POST /api/auth/login`.

## Changing Password While Logged In

If the user is already authenticated and wants to update their password, use the dedicated profile endpoint instead. No reset email is needed.

### PATCH /api/user/password

Requires a valid session (cookie or Bearer token).

<ParamField body="password" type="string" required>
  The new password. Minimum 8 characters.
</ParamField>

#### Response — 200 OK

```json title="Password changed"
{
  "success": true
}
```

<Note>
  `PATCH /api/user/password` does not invalidate existing sessions. If you want all other devices to be signed out after a password change, follow up with a call to `POST /api/auth/logout` on each active session.
</Note>

## Rate Limits

| Endpoint | Limit |
|---|---|
| `POST /api/auth/password/request` | 10 req / 10 min per IP · 3 req / 10 min per email |
| `POST /api/auth/password/reset` | 5 req / 10 min per IP |

<Warning>
  Exceeding a rate limit returns `429 Too Many Requests` with error code `RATE_LIMITED` and a `Retry-After: 60` header. Do not retry the request until the cooldown period has elapsed.
</Warning>

## Examples

<CodeGroup>
```bash title="Step 1 — Request reset link"
curl -X POST https://<host>/api/auth/password/request \
  -H "Content-Type: application/json" \
  -d '{"email": "ada@example.com"}'
```

```json title="Response"
{
  "success": true,
  "message": "Se o e-mail estiver cadastrado, as instruções serão enviadas."
}
```
</CodeGroup>

<CodeGroup>
```bash title="Step 2 — Apply new password"
curl -X POST https://<host>/api/auth/password/reset \
  -H "Content-Type: application/json" \
  -d '{
    "access_token": "<token-from-reset-link>",
    "password": "newS3cr3tPass"
  }'
```

```json title="Response"
{
  "success": true
}
```
</CodeGroup>

<CodeGroup>
```bash title="Change password while logged in"
curl -X PATCH https://<host>/api/user/password \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $TOKEN" \
  -d '{"password": "newS3cr3tPass"}'
```

```json title="Response"
{
  "success": true
}
```
</CodeGroup>
