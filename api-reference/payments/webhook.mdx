This endpoint is called **by AbacatePay**, not by your application directly. When a payment event occurs — such as a checkout being completed or a payout being processed — AbacatePay sends a signed HTTP POST request to this URL. The server validates the request's authenticity using two independent security checks before processing the event, ensuring that only genuine messages from AbacatePay can update registration and payout state.

<Warning>
  Do **not** call this endpoint from your own application or frontend. It is an inbound webhook exclusively for use by AbacatePay's payment infrastructure. Calling it directly without valid credentials will result in a `401` response.
</Warning>

## Endpoint

```http
POST /api/payments/webhooks/abacatepay
```

## Security

All requests must pass **both** of the following checks or the server responds with `401 Unauthorized`:

### 1. Webhook Secret Query Parameter

AbacatePay must include `?webhookSecret=YOUR_SECRET` in the request URL. This value must exactly match the webhook secret configured on the API server.

### 2. HMAC-SHA256 Signature Header

The request must include either an `X-Webhook-Signature` or `X-Abacate-Signature` header containing an HMAC-SHA256 signature computed over the **raw request body**. The server recalculates the expected signature and rejects the request if the values do not match.

<Note>
  The endpoint is registered with `rawBody: true` — it reads the unparsed byte stream before any JSON parsing so the HMAC calculation is performed against the exact bytes received.
</Note>

## Supported Event Types

| Event | Trigger |
|-------|---------|
| `checkout.completed` | A hosted checkout session was paid successfully. |
| `checkout.refunded` | A checkout payment was refunded. |
| `checkout.disputed` | A dispute was opened against a checkout payment. |
| `checkout.lost` | A checkout dispute was decided in the payer's favour. |
| `transparent.completed` | A transparent (direct) PIX charge was paid. |
| `transparent.refunded` | A transparent PIX charge was refunded. |
| `transparent.disputed` | A dispute was opened on a transparent PIX charge. |
| `transparent.lost` | A transparent charge dispute was lost. |
| `transparent.expired` | A transparent PIX charge expired without payment. |
| `transparent.cancelled` | A transparent PIX charge was cancelled. |
| `payout.completed` | A payout to an organizer's PIX key was successful. |
| `payout.failed` | A payout attempt failed. |
| `transfer.completed` | A transfer operation completed. |
| `transfer.failed` | A transfer operation failed. |

## Response Codes

| HTTP Status | Condition |
|-------------|-----------|
| `200` | Payload processed successfully. AbacatePay will not retry. |
| `400` | Payload could not be parsed as valid JSON or failed schema validation. |
| `401` | Webhook secret query param is missing/invalid **or** the HMAC-SHA256 signature does not match. |

<Tip>
  This endpoint is **idempotent**. AbacatePay may deliver the same event more than once in cases of network failure. The server deduplicates events by provider transaction ID, so retries are safe and will not result in duplicate registrations or payouts.
</Tip>

## Configuring the Webhook in AbacatePay

1. Log in to your AbacatePay dashboard.
2. Navigate to **Webhooks** → **Add Endpoint**.
3. Set the URL to `https://api.events-manager.app/api/payments/webhooks/abacatepay?webhookSecret=YOUR_SECRET`, replacing `YOUR_SECRET` with the webhook secret configured on the API server.
4. Select all event types you want to receive (see the table above for the full list).
5. Copy the signing secret shown after saving and configure it on the API server so the HMAC signature check can be performed.
