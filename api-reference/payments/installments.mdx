For ticket types that support installment payments, this endpoint lets you split the purchase into multiple PIX charges spread across calendar months. You specify the ticket, desired number of installments (2–12), and the participant's contact details. The API creates a registration, calculates the installment schedule, and returns the first installment's PIX QR code and copy-paste code so the attendee can pay immediately. Subsequent installment PIX codes can be generated on demand using the generate-pix endpoint described below.

<Note>
  Both endpoints on this page require a valid user session. Include your Bearer token in the `Authorization` header. The ticket type must have `allow_installments: true` and a configured `max_installments` value, otherwise the request will be rejected.
</Note>

## Create Installment Checkout

### Endpoint

```
POST /api/checkout/installments
```

### Request Body

<ParamField body="ticket_id" type="string (UUID)" required>
  UUID of the ticket type to purchase on installments.
</ParamField>

<ParamField body="quantity" type="integer" required>
  Number of tickets to purchase. Must be a positive integer (≥ 1).
</ParamField>

<ParamField body="installments" type="integer" required>
  Number of installment payments to create. Must be between **2** and **12** (inclusive).
</ParamField>

<ParamField body="participant_name" type="string" required>
  Full name of the lead participant. Must not be empty after trimming whitespace.
</ParamField>

<ParamField body="participant_email" type="string" required>
  Valid email address for the participant. Used for confirmation emails and installment reminders.
</ParamField>

<ParamField body="participant_phone" type="string">
  Phone number of the participant (optional).
</ParamField>

<ParamField body="participant_document" type="string">
  CPF, CNPJ, or other document number (optional). Required by some events for check-in validation.
</ParamField>

### Response

The response includes the created registration record (with `is_installment_payment: true`) and an `installments` array describing the full payment schedule. The **first installment** will already contain a `pix_qr_code_base64` image and a `pix_copy_paste` string so the attendee can pay immediately.

<ResponseField name="registration" type="object">
  The newly created `EventRegistration` record.

  <ResponseField name="registration.id" type="string (UUID)">
    Registration UUID.
  </ResponseField>

  <ResponseField name="registration.status" type="string">
    Initial status, typically `pending` until the first installment is confirmed.
  </ResponseField>

  <ResponseField name="registration.total_installments" type="integer">
    Total number of installments agreed at checkout.
  </ResponseField>

  <ResponseField name="registration.installment_plan_status" type="string">
    Status of the overall plan: `active`, `completed`, or `defaulted`.
  </ResponseField>

  <ResponseField name="registration.installments" type="array">
    Ordered list of `PaymentInstallment` objects.

    <ResponseField name="registration.installments[].id" type="string (UUID)">
      Unique identifier of this installment.
    </ResponseField>

    <ResponseField name="registration.installments[].installment_number" type="integer">
      Position in the schedule, starting at 1.
    </ResponseField>

    <ResponseField name="registration.installments[].total_installments" type="integer">
      Total installments in the plan (repeated on each item for convenience).
    </ResponseField>

    <ResponseField name="registration.installments[].amount" type="number">
      Amount due for this installment in BRL.
    </ResponseField>

    <ResponseField name="registration.installments[].due_date" type="string (ISO 8601)">
      Due date for this installment.
    </ResponseField>

    <ResponseField name="registration.installments[].status" type="string">
      Payment status: `pending`, `paid`, `overdue`, or `cancelled`.
    </ResponseField>

    <ResponseField name="registration.installments[].pix_qr_code_base64" type="string | null">
      Base64-encoded PNG of the PIX QR code. Present on installment 1 at creation time; generated on demand for subsequent installments.
    </ResponseField>

    <ResponseField name="registration.installments[].pix_copy_paste" type="string | null">
      Full PIX copy-paste (copia e cola) string. `null` until the PIX code has been generated.
    </ResponseField>

    <ResponseField name="registration.installments[].paid_at" type="string | null">
      ISO timestamp of when this installment was paid. `null` if not yet paid.
    </ResponseField>
  </ResponseField>
</ResponseField>

## Generate PIX for a Specific Installment

When an installment's PIX code has expired or the attendee needs a fresh code for an overdue installment, call this endpoint to generate a new one.

### Endpoint

```
POST /api/installments/:id/generate-pix
```

### Path Parameter

<ParamField path="id" type="string (UUID)" required>
  The UUID of the `PaymentInstallment` for which you want to generate a new PIX code.
</ParamField>

### Response

Returns the updated `PaymentInstallment` object with freshly generated `pix_qr_code_base64` and `pix_copy_paste` fields.

<Warning>
  Only the owner of the registration linked to the installment can request a new PIX code. Attempting to generate a PIX code for an installment belonging to another user returns `403 Forbidden`.
</Warning>

## Error Responses

| HTTP Status | Condition |
|-------------|-----------|
| `400` | Validation failure — e.g. `installments` outside 2–12, non-positive quantity. |
| `401` | Missing or invalid authentication token. |
| `403` | Ticket does not allow installments, event registration is closed, ticket is sold out, or the installment belongs to another user. |
| `404` | Installment ID not found (generate-pix endpoint). |
